# Review record format

Use `inventory` to create the manifest, then construct a separate ledger. Both use `schema_version: 1`. Do not edit the inventory; the reconciliation command checks its exact file hash against the ledger, then regenerates its contents from the current document and checks every field. The file hash binds the review to the declared check list as well as the document units.

## Top-level ledger

```json
{
  "schema_version": 1,
  "source_sha256": "copy the exact source.sha256 from inventory.json",
  "inventory_sha256": "copy the SHA-256 printed when inventory.json was created",
  "evidence": [
    {"id": "NOTE", "path": "supporting-note.md", "sha256": "SHA-256 of the evidence file bytes"}
  ],
  "records": []
}
```

`evidence` is optional. Its IDs are uppercase ASCII letters, digits, underscores, or hyphens, beginning with a letter and at most 32 characters. `DRAFT` is reserved. Paths are relative to the ledger's directory; absolute paths, parent traversal, and symlinks that leave that directory are rejected. Evidence files must be UTF-8 `.md` or `.txt`. To obtain a hash with the standard library:

```sh
python -c 'import hashlib,pathlib; print(hashlib.sha256(pathlib.Path("supporting-note.md").read_bytes()).hexdigest())'
```

Hashes are lowercase 64-character SHA-256 values. `source_sha256` hashes the source document. The separate required `inventory_sha256` hashes the entire saved inventory JSON file, including its check list, units, metadata, whitespace, and line endings. The `inventory` command prints it; the same Python command above can calculate it using `inventory.json` as the file name. Do not substitute the source hash for this inventory hash.

Any change to the saved inventory invalidates the existing ledger binding. Removing a check cannot convert missing reviews into complete coverage. Adding, renaming, or reordering checks and reformatting JSON also invalidate it. To change the review scope intentionally, create a new inventory and reassess the records against that scope before issuing a new ledger. Do not silently replace the ledger hash to clear an error.

Hashes establish correspondence to bytes, not source authenticity, authorship, or an authenticated edit history. This check detects inventory changes against the existing ledger; it cannot detect coordinated replacement of both artifacts by an author. Copy only evidence authorized for this review into the review directory.

## One record per unit/check pair

```json
{
  "unit_id": "U0003",
  "check": "source-support",
  "reviewer": "Example reviewer",
  "verdict": "revise",
  "quote": "The rollout is approved.",
  "comment": "The note describes a target subject to testing; approval is not established.",
  "status": "open",
  "proposed_text": "The rollout is proposed, subject to testing.",
  "support": [
    {"source_id": "NOTE", "quote": "The date is a target subject to testing.", "locator": "Planning decision"}
  ]
}
```

All seven fields through `status` are required and nonempty where they contain free text. `quote` must be an exact, case-sensitive substring of the named current unit, including any punctuation or line breaks it contains. It need not quote the entire block. Matching an arbitrarily short span does not prove the reviewer attended to the whole unit.

| Field | Accepted values or meaning |
| --- | --- |
| `unit_id` | ID generated by the current inventory |
| `check` | One of the checks declared in the inventory |
| `reviewer` | Supplied reviewer identity or an honest label such as `author self-check` |
| `verdict` | `no-change`, `revise`, `needs-evidence`, `not-applicable` |
| `comment` | Reviewer's explanation; source comments remain verbatim |
| `status` | `open`, `responded`, `closed`; self-reported, not independently confirmed |
| `resolution` | Required nonempty note for `closed`; optional otherwise |
| `response` | Required nonempty reply for `responded`; optional otherwise, separate from the original comment |
| `proposed_text` | Required only for `revise`; forbidden for other verdicts |
| `support` | Optional list except required and nonempty for `revise` |

A `needs-evidence` verdict cannot be closed. Change the recorded assessment only after considering the new evidence. `responded` records remain in the human-review list. A closed revision also remains there because closure alone does not prove that the proposed text is sound or implemented.

To cite another part of the current document:

```json
{"source_id": "DRAFT", "unit_id": "U0002", "quote": "The test group includes 24 accounts."}
```

Evidence citations use `source_id` and `quote`, with an optional free-text `locator`. A locator is useful to a reader but is not validated. `unit_id` is only allowed for `DRAFT` citations. Supporting quotes are checked for exact text presence in the named current source. The reviewer still judges whether that source supports the proposed wording, figures, qualifications, and attribution.

Duplicate unit/check pairs are all excluded from the counted pairs, even when one duplicate is otherwise valid. Unknown units, check names, verdicts, statuses, or fields are rejected or diagnosed. Separate reviewers' ledgers should be reconciled separately; merging them without selecting a designated record creates duplicates. Do not use record counts to infer agreement among reviewers.

## Segmentation and limits

Every contiguous block of nonblank physical lines is one unit. A heading followed immediately by prose is one block; a whole table without blank lines is one block. The helper does not parse Markdown and may split a fenced code block at a blank line. LF and CRLF line endings are preserved; isolated CR line endings are unsupported. A trailing newline does not create an extra blank physical line.

The entire source file is hashed, including blank lines and line endings. Unit hashes cover their exact UTF-8 text. Blank lines are listed but do not generate review slots. Any source-byte change invalidates the existing binding, even a blank-line edit.

Limits are 1 MiB per text file, 4 MiB per JSON input, 20,000 source lines, 5,000 units, 40,000 characters per unit, 12 checks, 20,000 unit/check pairs and ledger records, 16 evidence files, and 16 support citations per record. Unsupported or oversized inputs fail explicitly. A blank document is rejected; it cannot earn a vacuous complete result.

## Outputs and safe use

`inventory` writes one new JSON file. `reconcile` creates a new directory with `report.json` and `report.md`. Existing destinations are refused, including symlinks and hardlinks at file destinations. Source documents, evidence, inventories, and ledgers are read only. The script does not use the network or execute source content.

The JSON report preserves all supplied record fields, including invalid records, and lists which record numbers were counted. It reports current and ledger-recorded source and inventory hashes separately. Status counts use counted records only. The human-review list includes open work among counted records as well as every invalid or stale record. When source or inventory binding is unverified, no record is counted and missing pairs are not inferred from stale anchors or changed scope. The Markdown output quotes reviewer records as code so embedded headings or instructions remain visible as data.

The report does not certify substantive accuracy, omission detection, typography, grammar, reviewer identity, legal compliance, source authenticity, or the implementation of changes. If a source document changes after reading, the result describes the bytes read during this run, not later edits; rerun against a stable saved artifact.
